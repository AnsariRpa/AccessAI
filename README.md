# AccessAI — Navigate the World with Confidence

> **AI-powered accessibility intelligence layer for real-world navigation, entrance inspection, and community-verified mobility.**

AccessAI empowers individuals with mobility and physical accessibility needs to navigate urban environments with certainty. By pairing deterministic accessibility evaluation with Google Gemini multimodal intelligence (`gemini-3.8-flash`), AccessAI ensures travelers are never surprised by sudden stairs, broken elevators, or impassable curb cuts.

---

## 🌟 Core Philosophy: Epistemic Modesty & Provenance

Unlike conventional mapping tools that assume a venue or pathway is accessible unless proven otherwise, AccessAI adheres to **epistemic modesty**:
1. **Never Assume Accessibility**: A lack of recorded barriers does not guarantee an accessible path. Unverified pathways are explicitly labeled with confidence levels and unknown elements.
2. **Deterministic Grounding**: Physical accessibility constraints (steps, curb cuts, slope gradients) are evaluated deterministically rather than guessed by a generative model.
3. **Transparent Provenance Badging**: Every data point and route leg indicates its origin:
   - 🏛️ `OFFICIAL_SOURCE` — Municipal transit or government data.
   - 🛡️ `VERIFIED` — On-site physical accessibility audits.
   - 👥 `COMMUNITY_REPORTED` — Real-time crowdsourced reports with peer upvotes.
   - 🤖 `AI_INFERRED` — Multimodal vision estimates with explicit uncertainty caveats.

## 🚀 Key Features

### 1. 🧭 Personalized Accessibility Profiles
- **Mobility Types**:
  - **Manual Wheelchair**: Prioritizes gradual slopes (<1:12), zero steps, curb cuts, and wide doors.
  - **Power Wheelchair**: Requires wide elevators, heavy-load thresholds, and level transitions.
  - **Walker / Rollator**: Prioritizes ramped or level access over step-only passages.
  - **Crutches / Cane**: Prefers continuous handrails, short flights, and minimal distances.
  - **Stair Limited**: Avoids stairs while maintaining comfortable walking routes.
  - **Distance / Fatigue Limited**: Strictly minimizes travel duration and physical distance.
- **Customizable Avoidances**: Toggle avoidance of stairs, steep inclines, uneven cobblestones, revolving doors, or construction zones.

### 2. 🗺️ Evaluated Journey Planning & Route Comparison
- Side-by-side comparison of **Recommended Accessible Routes**, **Alternative Level Paths**, and **Cautioned Paths**.
- Visualized legs detailing surface types (paved sidewalks, curb ramps, elevator connectors, crosswalks).
- Deterministic accessibility scores (0–100) calculated against the traveler's active profile.
- Contextual route explanations generated by `gemini-3.8-flash`.

### 3. 🎙️ Turn-by-Turn Active Guidance Assistant
- **Interactive Step Telemetry**: Displays remaining travel distance and estimated duration.
- **Spoken Voice Guidance**: Built-in voice directions via the Web Speech API (`SpeechSynthesis`) with repeat and mute controls.
- **In-Transit Barrier Reporting**: Travelers can log a blocked ramp, construction hazard, or broken elevator with one tap during active transit.
- **Auto-Walk Simulation**: Allows travelers to preview the route step-by-step before departing.
- **Arrival Confirmation**: Summarizes distance covered, travel time, and step-free verification.

### 4. 📸 Multimodal Photo Inspector
- **AI Entrance & Obstacle Analysis**: Upload entrance photos or test curated scenarios (stairs, ADA-compliant ramps, blocked sidewalks).
- **Epistemic Output Breakdown**:
  - **Visual Observations**: Factual, verifiable visual features in the image.
  - **Detected Barriers**: Steps, high thresholds, narrow door clearances.
  - **Detected Features**: Compliant handrails, tactile paving, power-assist paddles.
  - **Unknown Elements**: Crucial details not visible from the current angle (e.g., interior elevators, side ramps).
  - **Prudent Recommendation**: Actionable advice on whether to proceed or seek an alternate entrance.

### 5. 📍 Searchable Accessible Places Discovery
- Curated index of accessible venues (Libraries, Healthcare Centers, Cafés, Transit Hubs).
- Live keyword search and category filtering.
- Dynamic compatibility match scores computed in real time based on active user preferences.
- Direct one-click routing from any venue card.

### 6. ⚠️ Community Intelligence & Real-Time Hazard Canvas
- Interactive vector map rendering streets, elevator waypoints, curb cuts, and active hazard pins.
- Community hazard feed with severity tags (`Critical Blocking`, `High`, `Medium`, `Low`).
- Peer confirmation and upvoting system to validate real-world conditions rapidly.

### 7. ♿ Universal Accessibility (A11y)
- High-Contrast Mode (WCAG AAA compliance).
- Screen-reader friendly semantic ARIA attributes and dialog roles.
- Minimum 44px touch targets on mobile and desktop interfaces.
- Respects reduced motion preferences.

## 🏗️ Technical Architecture

- **Frontend**: React 18, TypeScript, Tailwind CSS, Lucide React icons, Web Speech API.
- **Backend**: Node.js, Express, TypeScript (`tsx` for local dev, `esbuild` bundled CJS for production).
- **AI Integration**: Google GenAI SDK (`@google/genai`) connecting to `gemini-3.8-flash`.
- **Port**: Bound to port `3000` (required for reverse proxy and container deployment).

## 🛠️ Getting Started

### Prerequisites
- Node.js 18+ or Bun
- A Gemini API Key from [Google AI Studio](https://aistudio.google.com/)

### 1. Clone & Install Dependencies
```bash
git clone <your-repository-url>
cd access-ai
npm install
```

### 2. Configure Environment Variables
Create a `.env` file in the root directory:
```env
GEMINI_API_KEY="your-gemini-api-key-here"
APP_URL="http://localhost:3000"
```
*(See `.env.example` for reference)*

### 3. Run Development Server
```bash
npm run dev
```
Open [http://localhost:3000](http://localhost:3000) in your browser.

### 4. Production Build
```bash
npm run build
npm start
```
